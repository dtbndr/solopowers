# End Smoke Checks

Part of `solopowers:workstream-driven-development`. Human smoke testing happens once, here: after Final verification passes, before the final review ([final-review.md](final-review.md)). No per-slice smoke pauses.

1. Read `Final smoke checks` in `<folder>/brief.md`. Write `End smoke: pending` to `progress.md`.
2. "Authorized" means an explicit operator OK given in this session for that specific action. Approving `brief.md` alone is NOT authorization for provider-quota, deploy, DNS, email, or account actions; never run those without it.
3. For each check, run it yourself if you can and are authorized to; record the result. A failed agent-run check goes to step 7, never to step 5.
4. The remaining checks are P0/P1 checks the operator must do. Present them as a short numbered list, each with exact steps and the expected result, and ask the operator to report pass or fail per item.
5. Skip only when no check remains to run and none failed (the section is `None`, matched case-insensitively, or every check passed as agent-run): append `Smoke: skipped (agent-verified)` to `log.md` and write `End smoke: skipped`.
6. Record the outcome in `log.md` as `Smoke: passed|failed — <one-liner>` (`Smoke:` lines are committed with the final outcome). On a pass, run the full Final verification FIRST (skip the re-run only when no code changed since it last passed, so it is already current); only if it passes write `End smoke: passed` and the `Smoke: passed` line. If required Final verification fails, retain the failing command as a non-waivable Final verification blocker in the existing report; write no passed line and do not append `End smoke: failed` or enter the smoke fix/waiver loop. Resolve that blocker and rerun Final verification before recording smoke passed.
7. A failure is a P0/P1 finding. Write the check text and observed result (operator's report or your own output) to `<workspace>/end-smoke-findings.md` first, then write `End smoke: failed — <one-liner> (at <head7>)`, then enter the fix loop ([fix-loop.md](fix-loop.md), "End-smoke variant") with a fresh 4-round budget and `FIX_BASE` = current `HEAD`. Ledger lines use the slice grammar with the `End smoke:` prefix: `End smoke: fix round <R>/4 (<X> addressed, <Y> open — …; commits <a7>..<b7>)`, then `End smoke: escalated at cap — <Y> open` and `End smoke: Ruling (user): <finding> — <decision>`. The ledger is append-only; the last `End smoke:` state line wins (ignore `Ruling (user)` lines). At cap, present the unresolved failure to the operator as for slices; never round 5.
8. When the fix loop ends review clean through fixes, re-run the failed smoke check, then the full Final verification (all commands); only if both pass write `End smoke: passed` and log `Smoke: passed`. If a smoke check fails, refresh that finding in the existing report. Below the cap, append a new `End smoke: failed …` line and start the next round. If a smoke check still fails after the round-4 clean re-review, refresh its finding and append `End smoke: escalated at cap — <Y> open` (with the actual open P0/P1 count, at least 1); present that finding for a user ruling. This creates the durable cap checkpoint even though code review was CLEAN. Never append a fresh `failed` state or dispatch round 1 again. If required Final verification fails, retain it as a non-waivable Final verification blocker in the existing report; do not write an `End smoke: failed` line or enter the smoke waiver loop. When rulings accept failures without code changes, do not rerun those explicitly waived checks; run full Final verification and, only if it passes, write `End smoke: passed (rulings accepted)` and log it. When rulings direct fixes, rerun only the checks attached to currently directed findings after review-clean; do not rerun checks whose failures have an explicit acceptance ruling. If required Final verification fails, retain it as a non-waivable Final verification blocker; do not enter the smoke fix or waiver loop.
