# End Smoke Checks

For non-waivable Final verification failures, follow [Final Verification Blocker](verification-blocker.md).

Part of `solopowers:workstream-driven-development`. Human smoke testing happens once, here: after Final verification passes, before the final review ([final-review.md](final-review.md)). No per-slice smoke pauses.

1. Read `Final smoke checks` in `<folder>/brief.md`. Write `End smoke: pending` to `progress.md` and persist the complete required-check set before running or requesting any check. Keep this set and all per-check results through failures, fixes, and restarts; success requires every required check to pass or have an applicable named ruling.
2. "Authorized" means an explicit operator OK given in this session for that specific action. Approving `brief.md` alone is NOT authorization for provider-quota, deploy, DNS, email, or account actions; never run those without it.
3. For each check, first reuse a durable result recorded for the current applicable `HEAD`; do not repeat completed checks. On resume, reconcile any recorded failure into its finding and ledger transition before dispatching remaining checks. For failure after a fix-round rerun, recover the preceding fix-round number first and continue its budget (round 4 failure becomes cap escalation); never treat it as a fresh initial failure. If revision, predecessor, or transition is ambiguous, stop and ask. Run only checks with no valid saved result, if authorized; record each result with its revision. A failed agent-run check goes to step 7, never to step 5.
4. The remaining checks without a valid saved result are P0/P1 checks the operator must do. Present only those as a short numbered list, each with exact steps and the expected result, and ask the operator to report pass or fail per item.
5. Skip only when no check remains to run and none failed (the section is `None`, matched case-insensitively, or every check passed as agent-run): append `Smoke: skipped (agent-verified)` to `log.md` only if that exact outcome is absent, then write `End smoke: skipped`; on resume, reconcile either durable write by adding only the missing one, never duplicating the log line.
6. Record the outcome in `log.md` as `Smoke: passed|failed — <one-liner>` (`Smoke:` lines are committed with the final outcome). On a pass, run the full Final verification FIRST (skip the re-run only when no code changed since it last passed, so it is already current); only if it passes write `End smoke: passed` and the `Smoke: passed` line, appending the exact log outcome only if absent. For an initial-smoke blocker, after the passed outcome (including `passed (rulings accepted)`) and current verification are durable, mark the blocker `RESOLVED`; on resume reconcile either write and do not replay smoke. If required Final verification fails, route directly to [Final Verification Blocker](verification-blocker.md), which creates the report if absent; write no passed line and do not append `End smoke: failed` or enter the smoke fix/waiver loop. Resolve that blocker and rerun Final verification before recording smoke passed.
7. A failure is a P0/P1 finding. Write the check text and observed result (operator's report or your own output) to `<workspace>/end-smoke-findings.md` first, then identify the preceding smoke state. Only an initial failure with no prior fix round starts a fresh 4-round budget; a failed post-fix rerun continues the existing budget, and after round 4 escalates without restarting. If the predecessor cannot be established, stop and ask. For an initial failure, append `End smoke: failed — <one-liner> (at <head7>)` and enter the End-smoke variant of the fix loop with a fresh four-round budget. For a post-fix failure, append the failure checkpoint within the existing budget, or escalate at round four; never reset the budget. Set `FIX_BASE` = current `HEAD` for a newly authorized series. Ledger lines use the slice grammar with the `End smoke:` prefix: `End smoke: fix round <R>/4 (<X> addressed, <Y> open — …; commits <a7>..<b7>)`, then `End smoke: escalated at cap — <Y> open` and `End smoke: Ruling (user): <finding> — <decision>`. The ledger is append-only; the last `End smoke:` state line wins (ignore `Ruling (user)` lines). At cap, present the unresolved failure to the operator as for slices; never round 5.
8. When the fix loop ends review clean through fixes, re-run the failed smoke check and every other required check still outstanding or invalidated by code changes; reuse valid saved passes and honor only applicable named rulings. Then run full Final verification (all commands); record `End smoke: passed` and log `Smoke: passed` only when every required check is passed or explicitly disposed of and Final verification passes. If a smoke check fails, refresh that finding in the existing report. Below the cap, append a new `End smoke: failed …` line and start the next round. If a smoke check still fails after the round-4 clean re-review, refresh its finding and append `End smoke: escalated at cap — <Y> open` (with the actual open P0/P1 count, at least 1); present that finding for a user ruling. This creates the durable cap checkpoint even though code review was CLEAN. Never append a fresh `failed` state or dispatch round 1 again. If required Final verification fails, retain it as a non-waivable Final verification blocker in the existing report; do not write an `End smoke: failed` line or enter the smoke waiver loop. When rulings accept failures without code changes, do not rerun those explicitly waived checks; require every other required check to have a valid pass at the applicable revision or its own applicable named ruling. Then run full Final verification and, only if it passes, write `End smoke: passed (rulings accepted)` and log it only if that exact outcome is absent. For an initial-smoke blocker, mark it `RESOLVED` once the passed outcome and current Final verification are durable. When rulings direct fixes, after independent review-clean rerun checks attached to directed findings plus every other required check still outstanding or invalidated by the fix; reuse valid saved passes and do not rerun checks whose failures have an explicit acceptance ruling. Do not record smoke success until all required non-waived checks are passed or explicitly disposed of. If required Final verification fails, retain it as a non-waivable Final verification blocker; do not enter the smoke fix or waiver loop.
