# End Smoke Checks

For non-waivable Final verification failures, follow [Final Verification Blocker](verification-blocker.md).

Part of `solopowers:workstream-driven-development`. Human smoke testing happens once, here: after Final verification passes, before the final review ([final-review.md](final-review.md)). No per-slice smoke pauses.

1. Read `Final smoke checks` in `<folder>/brief.md`. Write `End smoke: pending` to `progress.md` and persist the complete required-check set before running or requesting any check. Keep this set and all per-check results through failures, fixes, and restarts; success requires every required check to pass or have an applicable named ruling.
2. "Authorized" means an explicit operator OK given in this session for that specific action. Approving `brief.md` alone is NOT authorization for provider-quota, deploy, DNS, email, or account actions; never run those without it.
3. For each check, first reuse a durable result recorded for the current applicable `HEAD`; do not repeat completed checks. On resume, reconcile any recorded failure into its finding and ledger transition before dispatching remaining checks. For failure after a fix-round rerun, recover the preceding fix-round number first and continue its budget (round 4 failure becomes cap escalation); never treat it as a fresh initial failure. If revision, predecessor, or transition is ambiguous, stop and ask. Run only checks with no valid saved result, if authorized; record each result with its revision. A failed agent-run check goes to step 7, never to step 5.
4. The remaining checks without a valid saved result are P0/P1 checks the operator must do. Present only those as a short numbered list, each with exact steps and the expected result, and ask the operator to report pass or fail per item.
5. Skip only when no check remains to run and none failed (the section is `None`, matched case-insensitively, or every check passed as agent-run): append `Smoke: skipped (agent-verified)` to `log.md` only if that exact outcome is absent, then write `End smoke: skipped`; on resume, reconcile either durable write by adding only the missing one, never duplicating the log line. For an initial-smoke blocker, hand off directly to [Final Verification Blocker](verification-blocker.md) for closeout; do not add another transition.
6. Record the outcome in `log.md` as `Smoke: passed|failed — <one-liner>` (`Smoke:` lines are committed with the final outcome). On a pass, follow [Final Verification Blocker](verification-blocker.md) for verification, revalidation, and closeout.
7. A failure is a P0/P1 finding. Write the check text and observed result (operator's report or your own output) to `<workspace>/end-smoke-findings.md` first, then identify the preceding smoke state. Only an initial failure with no prior fix round starts a fresh 4-round budget; a failed post-fix rerun continues the existing budget, and after round 4 escalates without restarting. If the predecessor cannot be established, stop and ask. For an initial failure, append `End smoke: failed — <one-liner> (at <head7>)` and enter the End-smoke variant of the fix loop with a fresh four-round budget. For a post-fix failure, append the failure checkpoint within the existing budget, or escalate at round four; never reset the budget. Set `FIX_BASE` = current `HEAD` for a newly authorized series. Ledger lines use the slice grammar with the `End smoke:` prefix: `End smoke: fix round <R>/4 (<X> addressed, <Y> open — …; commits <a7>..<b7>)`, then `End smoke: escalated at cap — <Y> open` and `End smoke: Ruling (user): <finding> — <decision>`. The ledger is append-only; the last `End smoke:` state line wins (ignore `Ruling (user)` lines). At cap, present the unresolved failure to the operator as for slices; never round 5.
8. When the fix loop ends review clean through fixes, hand off to [Final Verification Blocker](verification-blocker.md) for smoke revalidation and closeout; that procedure governs outstanding checks, named waivers, round budget, and success recording.
