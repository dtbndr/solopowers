# End Smoke Checks

For non-waivable Final verification failures, follow [Final Verification Blocker](verification-blocker.md). Reuse an established full Final verification pass while applicable to the current revision and verification conditions; rerun if stale or unestablished. Matching `HEAD` alone is not proof, and a passing run does not clear pending smoke obligations.

Part of `solopowers:workstream-driven-development`. Human smoke testing happens once, here: after Final verification passes, before the final review ([final-review.md](final-review.md)). No per-slice smoke pauses.

1. Read `Final smoke checks` in `<folder>/brief.md`. Write `End smoke: pending` to `progress.md` and persist the complete required-check set before running or requesting any check. Keep this set and all per-check results through failures, fixes, and restarts; success requires every required check to pass or have an applicable named ruling.
2. "Authorized" means an explicit operator OK given in this session for that specific action. Approving `brief.md` alone is NOT authorization for provider-quota, deploy, DNS, email, or account actions; never run those without it.
3. For each check, first reuse a durable result recorded for the current applicable `HEAD`; do not repeat completed checks. On resume, reconcile any recorded failure into its finding and ledger transition before dispatching remaining checks. For failure after a fix-round rerun, recover the preceding fix-round number first and continue its budget (round 4 failure becomes cap escalation); never treat it as a fresh initial failure. If revision, predecessor, or transition is ambiguous, stop and ask. Run only checks with no valid saved result, if authorized; record each result with its revision. A failed agent-run check goes to step 7, never to step 5.
4. The remaining checks without a valid saved result are P0/P1 checks the operator must do. Present only those as a short numbered list, each with exact steps and the expected result, and ask the operator to report pass or fail per item.
5. Skip only when no check remains to run and none failed (the section is `None`, matched case-insensitively, or every check passed as agent-run). Require current full Final verification; if it fails, use [Final Verification Blocker](verification-blocker.md). If an initial blocker is pending, route to that procedure before writing success; it owns recording the canonical paired skip outcome and resolving the blocker after verification is durable. Otherwise append `Smoke: skipped (agent-verified)` to `log.md` only if absent, then write `End smoke: skipped`. On resume reconcile the pair by adding only a missing write; never duplicate the log line.
6. Require every applicable required check to pass or have an applicable named ruling, and current full Final verification, before recording success. If verification fails, use [Final Verification Blocker](verification-blocker.md); do not write success. Revalidate required checks invalidated by applicable code changes after independent review-clean; reuse still-current passes and applicable named rulings. If an initial blocker is pending, route to [Final Verification Blocker](verification-blocker.md) before writing success; that procedure owns the canonical paired pass outcome and blocker resolution. Otherwise record `Smoke: passed — <one-liner>` in `log.md` and `End smoke: passed` in `progress.md`. On resume reconcile either durable write by adding only the missing one, never duplicating a log line. Keep named-ruling success in its existing closeout route; do not duplicate that procedure. An initial operator-reported failure goes directly to step 7, as does a failed agent-run check.
7. A failure is a P0/P1 finding. Write the check text and observed result (operator's report or your own output) to `<workspace>/end-smoke-findings.md` first, then identify the preceding smoke state. Only an initial failure with no prior fix round starts a fresh 4-round budget; a failed post-fix rerun continues the existing budget, and after round 4 escalates without restarting. If the predecessor cannot be established, stop and ask. For an initial failure, append `End smoke: failed — <one-liner> (at <head7>)` and enter the End-smoke variant of the fix loop with a fresh four-round budget. For a post-fix failure, return here from step 8 and append the failure checkpoint within the existing budget, or escalate at round four; never reset the budget. Set `FIX_BASE` = current `HEAD` for a newly authorized series. Ledger lines use the slice grammar with the `End smoke:` prefix: `End smoke: fix round <R>/4 (<X> addressed, <Y> open — …; commits <a7>..<b7>)`, then `End smoke: escalated at cap — <Y> open` and `End smoke: Ruling (user): <finding> — <decision>`. The ledger is append-only; the last `End smoke:` state line wins (ignore `Ruling (user)` lines). At cap, present the unresolved failure to the operator as for slices; never round 5.
8. After the fix loop ends review clean, rerun outstanding or invalidated required smoke checks, reusing still-current passes and applicable named rulings. A failed rerun returns to step 7 with the established round; round-four failure escalates there even if review is CLEAN. If all applicable checks pass or have applicable named rulings, require current full Final verification. If verification fails, use [Final Verification Blocker](verification-blocker.md). If a blocker is pending, route to its canonical closeout before writing success; it owns the paired pass outcome and resolution. Otherwise record `Smoke: passed — <one-liner>` in `log.md` and `End smoke: passed` in `progress.md`. On resume reconcile either durable write without duplication.
