# Isolation Choice

Part of `solopowers:workstream-driven-development`. Run it once per workstream, after the pre-flight scan findings are surfaced and before dispatching the first implementer. Never ask again on resume (read the mode from `log.md`).

The agent recommends with a one-line reason; the operator decides:

- Recommend **worktree** when the main checkout must stay usable (other work in flight, dirty tree, long workstream). Recommend **branch** when the work is small and the tree is clean.
- Mention that worktrees do not carry gitignored files (`.env`, virtualenvs, `node_modules`), so the final smoke check is cheaper in the operator's normal checkout; that is a reason to lean toward branch for small work.
- Example: "I recommend a branch: the tree is clean and this is three small slices, so the final smoke check can run in your normal checkout. Branch or worktree?"
- **Worktree mode:** invoke `solopowers:using-git-worktrees` ONCE. The workstream folder MUST already be committed on the base before the worktree is created, meaning it is tracked AND `git status --porcelain -- <folder>` is empty (no uncommitted edits): a fresh worktree does not contain untracked files, so `wsd-workspace <folder>/slices.md` would fail and a hand-copied folder would abort the later merge. Brainstorming normally already committed it, so this is the rare path. If it is not committed, tell the operator and offer exactly two options (agent recommends with a one-line reason; operator decides): (a) commit ONLY the workstream folder (planning docs, no implementation code, explicit paths) on the current base branch, then create the worktree; planning docs may go on the base branch, implementation work never does; or (b) switch the isolation choice to branch mode. Never copy the folder into the worktree by hand. The worktree's branch is `ws/<slug>` (same as branch mode). If `using-git-worktrees` cannot create the worktree (e.g. a sandbox permission error), do NOT continue in the current directory: stop and offer branch mode instead.
- **Branch mode (inline, no call to `using-git-worktrees`):** require a clean working tree (the workstream folder itself may be the only uncommitted content; branch mode only). Never commit workstream work directly onto the repo's default branch: if currently on the default branch, create the branch from it; if on another branch, stop and ask. Create it with `git switch -c ws/<slug>`, where `<slug>` is the workstream folder name with its leading `YYYY-MM-DD-` stripped (the same slug used for `WORKSPACE_SLUG`).

## log.md

Brainstorming already created `<folder>/log.md` with its `# <Topic> Workstream Log` header; do NOT re-create it. Right after isolation setup, APPEND a first body line to it INSIDE the isolation unit, `Isolation: <branch|worktree> — branch <name>`, and commit that as the first commit on the feature branch or worktree (never on the default branch). In branch mode, if the workstream folder is not yet committed on the base, include it in this first commit (worktree mode requires it committed already). Apply any pre-flight edits agreed with the operator inside the isolation unit and commit them there (after the `Isolation:` commit). Then append the pre-flight result line (see [preflight.md](preflight.md)).
